The Opportunity

Complex workflows.
Natural language.

Spendflo's core workflows — vendor renewal tracking, contract reviews, budget reallocation requests, and spend analysis — require navigating multiple modules, filtering data tables, and triggering multi-step approval flows. For finance leads managing 50+ vendors, this was a daily grind.

The LLM-powered opportunity was clear: if Flo could understand "Renew Salesforce contract for next year at the same terms" and execute it end-to-end, we could eliminate 80% of the clicks for the most common power-user tasks.

The Design Challenge

AI UX is a new design language

Unlike traditional UI, an AI assistant has no fixed interaction model. Users don't know what's possible, commands fail unpredictably, and the line between "the AI understood me" and "the AI did something wrong" is blurry. Designing Flo required building a new design grammar from scratch.

My primary design challenge: how do you design an interface that feels capable without feeling magical? Users needed to trust Flo's actions, understand its limitations, and maintain a sense of control at every step.

Design Principles for AI UX

Built on three guardrails

01

Transparent intent

Flo always shows what it understood before it executes. A confirmation step — "I'll renew the Salesforce contract for $48,000. Confirm?" — builds trust and prevents costly errors. No silent actions.

02

Graceful failure

When Flo doesn't understand or lacks permissions, it says so clearly and suggests the manual path. "I can't edit that contract directly, but here's the link to do it in 2 clicks." No dead ends.

03

Progressive capability discovery

Flo surfaces what it can do contextually — on the Vendors page it suggests vendor-specific prompts; on Budgets it surfaces spend queries. Users discover capabilities through use, not documentation.

Design Process

Prompt engineering meets product design

01

Use-Case Prioritisation Workshop

Facilitated a 2-hour workshop with PM, Engineering, and Customer Success to map the 30 most common power-user tasks. Scored each against frequency, time cost, and AI feasibility. Selected the top 8 use cases for V1 — the ones with the highest ROI if automated.

02

Conversation Flow Mapping

For each of the 8 use cases, mapped the full conversation flow: user intent → Flo's interpretation → confirmation state → execution → result. This wasn't wireframing — it was screenwriting. Every edge case (ambiguous input, partial match, permission error) needed a scripted response.

03

Prototype + Wizard of Oz Testing

Built a Figma prototype simulating Flo's responses. Ran "Wizard of Oz" testing: users typed natural language prompts; I manually triggered the right responses to simulate AI behaviour. This let us test conversation design before any LLM integration. Found 14 edge cases we hadn't designed for.

04

Interface Design — The Flo Overlay

Designed Flo as a persistent overlay (not a modal or sidebar) accessible from anywhere in the app via Cmd+K. The overlay shows the current context (which page you're on), recent actions, and a suggested prompts rail. The conversation UI distinguishes between user messages, Flo's reasoning, and Flo's actions.

05

Prompt Engineering Collaboration

Worked directly with the ML engineer to write and test system prompts. My role: ensure Flo's outputs were well-structured for the UI, that tone was professional but not robotic, and that error states had enough context for users to self-recover. Ran 200+ test prompts across all use cases.

Key Design Decision

The confirmation layer that built trust

The single most debated design decision was whether to add a confirmation step before execution. The AI team wanted one-shot execution for speed. I pushed for explicit confirmation.

"The confirmation step cut abandonment by 34%. Users trusted Flo because they could see what it was about to do before it did it."

— Post-launch data, 30 days after Flo V1 launch

Strategic Lens

AI UX is product strategy

Designing Flo taught me that AI features aren't UX additions — they're product strategy decisions. The question isn't "how should this interface look?" but "what should the AI be allowed to do autonomously, and where should it defer to the human?" That's a business and ethics question as much as a design question.

The most important skill I brought to this project was facilitation: getting engineering, product, legal, and CS aligned on capability boundaries before a single prompt was written. Without that alignment, the AI would have been over-scoped and the UX would have been built on false promises.
